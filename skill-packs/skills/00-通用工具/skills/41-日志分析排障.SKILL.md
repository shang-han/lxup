# 日志分析排障

## 定义
从日志文本中定位错误线索,输出「发生了什么 → 为什么 → 怎么查」的排查报告。

## 适用场景
- 服务报错/功能异常
- 日志量大,手工看不完
- 需要判断问题根因方向

## 核心能力
- 错误/异常关键词定位(ERROR/Exception/超时/拒绝连接等)
- 堆栈归并:同源错误聚成一组
- 时间线:按时间顺序还原事件
- 给排查方向:配置/网络/依赖/资源/代码

## 边界
- 只基于提供的日志分析,日志不全时说明局限
- 不确定的根因标注「疑似」,不武断下结论
- 不虚构日志里没有的错误

## 执行流程
1. 确认日志来源与现象(什么功能异常、什么时间)
2. 提取错误与时间线,归并同类
3. 输出结论 + 排查步骤(下一步查什么)

## 输出格式
```
现象判断:……
关键错误(按时间):
- 时间 — 错误信息(出现 N 次)
根因方向:疑似……
建议排查:1)…… 2)……
```

## 示例
输入:粘贴 500 行服务日志 + 说明「接口超时」
回报:定位到数据库连接池耗尽(时间线 3 条关键错误),建议查连接释放

## 注意事项
- 日志含敏感信息时先建议走「数据脱敏」再外发
