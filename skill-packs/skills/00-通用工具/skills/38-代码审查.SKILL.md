# 代码审查

## 定义
按固定维度审查代码并输出分级问题清单(严重/一般/建议),每条带位置、原因与改法。

## 适用场景
- 提交/上线前自查
- 接手或合并他人代码
- 定位偶发问题的隐患

## 核心能力
- 维度:正确性、边界与异常、安全(注入/密钥/权限)、性能、可读性
- 问题分级:严重(必须改)/ 一般(建议改)/ 建议(可选)
- 每条含:文件位置、问题、为什么、怎么改

## 检查清单库(逐项对照,命中的才报)
- 安全:SQL/命令拼接注入、硬编码密钥与口令、越权与输入校验缺失、敏感信息写日志、上传类型未校验、危险反序列化、随机数用于安全场景
- 正确性:空值与边界、并发竞态、异常被吞、类型转换、浮点比较、资源未释放
- 性能:循环内查询、N+1、大对象拷贝、阻塞调用放热点路径
- 可维护性:命名不清、重复代码、函数过长、改动无对应测试

## 质量关卡(输出前逐条自查)
1. 每条问题含:位置 + 触发条件 + 影响 + 改法,可独立复现
2. 假阳性自查:不确定的标「需确认」,不凑数
3. 同一根因的问题合并为一条
4. 总体评价只谈代码,不评作者

## 边界
- 只审代码,不改代码(用户要求时再给修改)
- 不虚构问题

## 执行流程
1. 通读代码,按检查清单逐维度对照
2. 汇总问题,去重,分级排序
3. 过质量关卡,输出问题清单 + 总体评价(2-3 句)

## 输出格式
```
总体评价:……
严重(必须改):
1. 文件:行 — 问题 / 触发条件 / 影响 / 改法
一般 / 建议:同上
```

## 示例
输入:粘贴一段接口处理代码
回报:1 个严重(未校验空值)、2 个一般(异常吞掉、重复查询)、1 个建议

## 注意事项
- 用户指定了审查焦点(如只看安全)时按焦点来
