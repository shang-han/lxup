# 周报月报生成

## 定义
把用户提供的零散工作要点,整理成「成果 / 进行中 / 计划 / 风险」结构的汇报文本。

## 适用场景
- 每周/每月要交工作汇报
- 只记得零散事项,需要梳理成正式结构
- 汇报要发给不同对象(上级/团队/客户)

## 核心能力
- 结构:本周成果、进行中、下周计划、风险与求助
- 语气适配:正式(给上级)/ 简明(给团队)
- 量化表达:把模糊描述改成可量化的成果句

## 模板库
- 研发岗模板:
```
一、本周成果
- 完成【功能/模块】(耗时 X 天,已上线/已提测)
- 修复【问题】(影响范围,已发布)
二、进行中
- 【事项】(进度 X%,预计【日期】完成)
三、下周计划
- 【事项】(目标与依赖)
四、风险与求助
- 【风险】(影响,需要【谁】协助)
```
- 运营/行政岗模板:每板块开头先给数据(「本周新增用户 N,环比 ±M%」),再列事项
- 给团队的简洁版:每板块最多 1 行,只保留关键变化

## 质量关卡(输出前逐条自查)
1. 每条以动词开头(完成/修复/推进/上线/跟进)
2. 有数字的写数字;「很多/大量/不久」等模糊词已替换或已向用户追问
3. 没有内容的板块写「无」,不硬凑
4. 所有事项与用户原话一致,未新增用户没做过的工作

## 边界
- 只用用户提供的事实,不编造完成度与数据
- 不做绩效评价与自我表扬的夸大表述

## 执行流程
1. 收集要点,不足的板块向用户追问一句(如"本周有无风险/需要协助?")
2. 按模板归类,事项控制在每板块 3-5 条
3. 过一遍质量关卡,再输出

## 输出格式
按「一、本周成果 / 二、进行中 / 三、下周计划 / 四、风险与求助」输出,默认 Markdown 便于复制。

## 示例
输入:「这周做了登录模块、修了两个 bug、下周做支付」
回报:结构化周报(成果 2 条、计划 1 条,其余板块标「无」)

## 注意事项
- 用户给的信息太少时先追问,不脑补工作内容
