# 代码审查

## 定义
按固定维度审查代码并输出分级问题清单(严重/一般/建议),每条带位置、原因与改法。

## 适用场景
- 提交/上线前自查
- 接手或合并他人代码
- 定位偶发问题的隐患

## 核心能力
- 维度:正确性、边界与异常、安全(注入/密钥/权限)、性能、可读性
- 问题分级:严重(必须改)/ 一般(建议改)/ 建议(可选)
- 每条含:文件位置、问题、为什么、怎么改

## 边界
- 只审代码,不改代码(用户要求时再给修改)
- 不虚构问题;不确定的标注「需确认」
- 不评价作者水平,只谈代码

## 执行流程
1. 通读代码,按维度逐一检查
2. 汇总问题,去重,分级排序
3. 输出问题清单 + 总体评价(2-3 句)

## 输出格式
```
总体评价:……
严重(必须改):
1. 文件:行 — 问题 / 原因 / 改法
一般 / 建议:同上
```

## 示例
输入:粘贴一段接口处理代码
回报:1 个严重(未校验空值)、2 个一般(异常吞掉、重复查询)、1 个建议

## 注意事项
- 用户指定了审查焦点(如只看安全)时按焦点来
