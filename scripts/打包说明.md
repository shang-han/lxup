# LXUP 出厂包（工厂包）打包说明

> 面向"接手的人 / 换机器的人"。所有路径都以仓库根 `D:\lxup` 为例，实际由脚本自动推导，
> 换盘符、换机器不用改脚本。

## 0. 一句话口径

**工厂包 = 更新包口径 + openclaw/codex 引擎本体**：
在"更新包"（代码 + control-ui/dist + 便携 python + 便携 node）的基础上，
额外带上 OpenClaw、Codex 两套引擎本体与一份**脱敏后**的网关配置，让客户机解压即可首次启动。

仓库内相关脚本（本目录 `scripts/`）：

| 文件 | 作用 |
| --- | --- |
| `build-factory.py` | 打出厂包 zip（含全部排除/脱敏逻辑）。便携 python 跑它 |
| `build-release.ps1` | 一键：重建 `LXUP启动器.exe` → 打包 → 自动验证 |
| `build-portable.ps1` | 老的"更新包/便携包"脚本（robocopy + tar 口径），出厂包不用它，但脱敏口径与它一致 |
| `打包说明.md` | 本文 |

> 历史脚本 `D:\lxup-release-2.4.0\build_factory.py`（不在 git 里）是本仓库版的前身，
> 逻辑已完整搬进 `scripts/build-factory.py`，只把写死路径改成推导。保留它做对照，别删。

## 1. 路径口径（脚本怎么找东西）

- `ROOT` = `build-factory.py` 所在目录的上级，即 `os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`。
  脚本必须放在 `<ROOT>/scripts/` 下，移动脚本就等于换 ROOT。
- 便携 python = `ROOT/runtime/python/cpython-3.11*/python.exe`（glob 探测）。
  注意 `runtime/python/` 下可能同时躺着**旧空壳目录** `cpython-3.11-windows-x86_64-none`
  （不进包，已在排除表里）和真正在用的 `cpython-3.11.15-windows-x86_64-none`。
  探测规则：优先带 patch 号的目录 → patch 号大的优先 → 同分时优先装了 PyInstaller 的那个。
  手动查询：`<任一python> scripts\build-factory.py --locate-python`
- 版本号 = `ROOT/runtime/version.json` 的 `version` 字段（当前 `2.4.0`）。读不到就直接报错退出，
  因为版本号决定产物名，不能猜。
- 输出目录 `OUT` = 环境变量 `LXUP_OUT`；未设置时为 `<ROOT> 的上级>\lxup-release-<version>`
  （即默认 `D:\lxup-release-2.4.0`）。不存在会自动 `makedirs`。
- 产物名固定 `LXUP-factory-v<version>.zip`。查询：`python scripts\build-factory.py --print-zip`
- **Python 服务/打包一律用便携 python，不要用系统 `python`**（系统 python 没装依赖）。
  往便携 python 里装包要加 `--break-system-packages`（PEP 668 externally-managed）。

## 2. 三必带（缺一个，客户机网关就起不来）

| # | 必带内容 | 谁负责 | 不带会报什么 |
| --- | --- | --- | --- |
| ① | **脱敏后的 `runtime/openclaw-home/openclaw.json`** | `build-factory.py` 的 `_sanitized_openclaw_config()` 单独写进 zip（`runtime/openclaw-home` 整目录本来是被排除的） | 网关直接拒绝就绪：`Missing config`（含 `gateway.mode` 相关校验失败） |
| ② | **`runtime/openclaw-home/plugins/` 整目录**（约 263 MB，四个插件本体：deepseek / qqbot / weixin / wecom，配置里 `plugins.load.paths` 指向它们） | `build-factory.py` 在排除整目录之后，再单独 walk 一遍 plugins 塞回包 | 网关配置校验失败：`plugin path not found` |
| ③ | **便携 node 旁的 npm**：`runtime/data/npm.cmd`、`npx.cmd`、`node_modules/npm/bin/npm-cli.js` | 由 `bootstrap-openclaw.bat` **自动 stage**：它在 `call npm install openclaw` 之后，把当时系统里的 npm（`npm.cmd`/`npx.cmd`/`node_modules\npm`）拷进 `runtime/data\`（node.exe 旁）。母版只要跑过一次 bootstrap 就自带 npm，随 `node.exe` 被 walk 打进包，`build-factory.py` 无需特殊处理（**别把它加进排除表**）。缺了就重跑 `bootstrap-openclaw.bat`，**不要手工拷** | OpenClaw 装插件时报 `'npm.cmd' 不是内部或外部命令` |

`build-factory.py` 在**开始写 zip 之前**会预检 ①②：母版 `openclaw.json` 不存在、或
`openclaw-home/plugins/` 不存在/为空，直接 `[FATAL]` 退出，不会留下一个"看起来打完了"的残缺包。
③ 靠 §6 ① 的关键条目检查兜底（`runtime/data/npm.cmd`、`node_modules/npm/bin/npm-cli.js` 必须在包里）。

## 3. 脱敏 / 排除规则清单（改动前必读）

### 3.1 排除目录 `EXCLUDE_DIRS`

`.git`、`__pycache__`、`node_modules/.cache`、
`runtime/openclaw-home`（**整目录**，只由 §2 ①② 单独补回配置与插件）、
`runtime/hermes-home`、`runtime/codex-home`、`runtime/logs`、
`ai-assistant/data`、
`runtime/python/cpython-3.11-windows-x86_64-none`（旧空壳解释器，避免包里两份 python）、
`runtime/python/.temp`、`runtime/python/.lock`、
`engines`（`bootstrap-codex.bat` 会把 openai/codex 协议参考源码 clone 到 `engines\codex`——运行时不需要它；但 `call` 修复后那步 clone 现在会真的执行，若不排除、clone 一旦成功就会把上百 MB 参考源码误打进客户包）

### 3.2 排除文件 `EXCLUDE_FILES`

`.sidecar.ready`、`runtime/data/.sidecar.ready`（就绪标记，带上会让客户机误判已初始化）、
`runtime/data/gateway.db` 及 `-wal` / `-shm` / `-journal`（本地授权/会话数据）、
`runtime/data/sidecar.log`、
`package-lock.json`、
`_swap_launcher.bat`、
`LXUP启动器.exe.new`、`LXUP启动器.exe.old`（exe 自更新的中间产物）、
`runtime/python/.gitignore`

另外无条件跳过：所有 `*.pyc`；os.walk 层面剪掉 `.git` 与 `__pycache__` 子目录。

> **`EXCLUDE_FILES` 是按"相对仓库根的完整路径"精确匹配的**，不是按文件名递归匹配。
> 所以 `package-lock.json` 只排除仓库根那一份，`control-ui/package-lock.json`、
> `runtime/openclaw/package-lock.json`、`runtime/codex/package-lock.json` 仍会进包（无害，npm 装包更快）。
> 同理 `.sidecar.ready` 只排除根目录那份，`runtime/data/` 下那份是单独列出来的。
> 要新增排除项，写完整相对路径。

### 3.3 `openclaw.json` 脱敏口径（`_sanitized_openclaw_config()`）

1. `gateway.auth.token` → 固定字符串 `dev-local-token`
2. **递归**遍历整个配置树（dict + list），凡 key 名为 `apiKey` 且值为非空字符串 → 置为 `""`
3. `channels` → 整个替换为 `{}`（清空微信/QQ/企微等通道绑定）
4. 其余字段（models/providers 结构、plugins.entries、plugins.load.paths、agents、skills 等）**原样保留**，
   否则客户机没有可用模型与插件路径
5. 序列化：`json.dumps(..., ensure_ascii=False, indent=2)`，UTF-8 写入

### 3.4 workspace 三文件置空 `WORKSPACE_BLANK_FILES`

`runtime/workspace/USER.md`、`MEMORY.md`、`IDENTITY.md` —— 这三个会被 AI 边用边填真实个人信息，
进包时**保留条目但内容置为 0 字节**（不是删除，删除会让首启行为不一致）。

### 3.5 中文文件名 UTF-8 标志

每个 zip 条目都 `info.flag_bits |= 0x800`。
少了它，`LXUP启动器.exe`、`龙虾U盘使用说明.html` 在 Linux `unzip` 下会变 GBK 乱码。

### 3.6 打包输出

结束打印 版本 / 仓库根 / 文件数 / 未压缩 MB / 压缩后 MB / **sha256** / 产物路径。
sha256 用于发版登记（更新服务器会动态算，但出厂包交付时人工核对一次）。

## 4. 重建 `LXUP启动器.exe`（完整命令）

启动器源码 = 仓库根 `launcher_gui.py`（纯标准库：tkinter + urllib + subprocess，无第三方依赖），
图标 = 仓库根 `LXUP-icon.ico`，产物名 = `LXUP启动器.exe`，onefile + windowed。

用**便携 python** 跑 PyInstaller（便携 python 的 site-packages 里已装 pyinstaller 6.x；
若缺：`& $PY -m pip install pyinstaller --break-system-packages`）：

```powershell
$ROOT = "D:\lxup"                                   # 换机器时改成实际仓库根
$PY   = "$ROOT\runtime\python\cpython-3.11.15-windows-x86_64-none\python.exe"
$TMP  = Join-Path $env:TEMP ("lxup-exe-" + (Get-Date -Format yyyyMMdd-HHmmss))
New-Item -ItemType Directory -Path $TMP -Force | Out-Null

& $PY -m PyInstaller --noconfirm --clean --onefile --windowed `
  --name "LXUP启动器" `
  --icon "$ROOT\LXUP-icon.ico" `
  --distpath "$TMP\dist" `
  --workpath "$TMP\build" `
  --specpath "$TMP" `
  "$ROOT\launcher_gui.py"
if ($LASTEXITCODE -ne 0) { throw "PyInstaller 失败" }

# 构建产物必须复制回仓库根覆盖，打包时才会进包
Copy-Item -LiteralPath "$TMP\dist\LXUP启动器.exe" -Destination "$ROOT\LXUP启动器.exe" -Force
```

三个坑：

1. **`--distpath/--workpath/--specpath` 必须指到仓库外**（这里用 `%TEMP%`）。
   `build-factory.py` 的排除表里**没有** `build/`、`dist/`，落在仓库根会把几十 MB 构建垃圾打进客户包。
2. **复制回根之前先关掉正在跑的启动器**（`stop-all.bat` 或任务管理器），否则文件被占用，`Copy-Item` 失败。
3. exe 是自更新入口：客户机升级时会下载 `.new`、退出时替换、旧的备份成 `.old`，
   这两个中间文件已在排除表里，别从排除表删掉。

## 5. 打包步骤

### 5.1 一键（推荐）

```powershell
cd D:\lxup
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-release.ps1
# 只打包+验证，不重建 exe：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-release.ps1 -SkipExe
# 指定输出目录：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-release.ps1 -OutDir "E:\deliver"
```

`build-release.ps1` 依次做：探测便携 python → 重建 exe 并复制回仓库根 → 跑 `build-factory.py` 打包
→ 自动验证（§6 ①② 两步）。任一步失败立刻停并报出是哪一步。

### 5.2 手动

```powershell
cd D:\lxup
$PY = "$PWD\runtime\python\cpython-3.11.15-windows-x86_64-none\python.exe"
& $PY scripts\build-factory.py
# 换输出目录：
$env:LXUP_OUT = "E:\deliver"; & $PY scripts\build-factory.py; Remove-Item Env:LXUP_OUT
```

打包前确认：`runtime/version.json` 的 version 是本次要发的号；`LXUP启动器.exe` 是新的（§4）；
母版上不要有正在写的临时文件。打包耗时主要在压缩 node.exe(91 MB)、python、plugins(263 MB)。

## 6. 验证三步

### ① 关键条目检查（必须存在 / 必须不存在）

必须存在：

```
runtime/data/node.exe     runtime/data/npm.cmd       runtime/data/npx.cmd
runtime/data/node_modules/npm/bin/npm-cli.js
runtime/openclaw-home/openclaw.json                  （脱敏版）
runtime/openclaw-home/plugins/…                      （plugins.load.paths 里四个路径各自至少 1 个文件）
runtime/python/cpython-3.11.<n>-windows-x86_64-none/python.exe   （验证脚本按通配检查，不写死 patch 号）
runtime/workspace/USER.md  runtime/workspace/MEMORY.md  runtime/workspace/IDENTITY.md   （三个都必须 0 字节）
sidecar/main.py           control-ui/dist/index.html  ai-assistant/server.js  skill-packs/manifest.json
runtime/openclaw/node_modules/openclaw/openclaw.mjs   （网关入口本体）
```

必须不存在：

```
runtime/data/gateway.db(-wal/-shm/-journal)   runtime/data/.sidecar.ready   runtime/data/sidecar.log
runtime/hermes-home/…   runtime/codex-home/…   runtime/logs/…   ai-assistant/data/…
.git/…   __pycache__/…   *.pyc   package-lock.json
runtime/python/cpython-3.11-windows-x86_64-none/…   （旧空壳解释器）
LXUP启动器.exe.new / .old
```

手动一行版（`build-release.ps1` 会自动跑等价检查）：

```powershell
& $PY -c "import zipfile,sys; z=zipfile.ZipFile(sys.argv[1]); n=set(z.namelist()); \
req=['LXUP启动器.exe','runtime/openclaw-home/openclaw.json','runtime/data/node.exe','runtime/data/npm.cmd']; \
bad=['runtime/data/gateway.db','runtime/data/.sidecar.ready']; \
print('missing:',[r for r in req if r not in n]); print('leaked:',[b for b in bad if b in n])" `
  "D:\lxup-release-2.4.0\LXUP-factory-v2.4.0.zip"
```

### ② 密钥泄露扫描（**绝不硬编码真实密钥**）

原则：验证脚本/文档里**不许出现任何真实 token、apiKey 明文**。做法是运行时从母版
`D:\lxup\runtime\openclaw-home\openclaw.json` 递归提取所有非空 `apiKey` / `token` 值
（母版当前有 3 处：`gateway.auth.token` + 2 个 provider 的 `apiKey`），
再拿这些值去**包里每一个文件**做字节级子串搜索，命中即失败。
这样换密钥、加密钥都不用改验证代码，也不会把密钥写进仓库。

同时校验包内那份 `runtime/openclaw-home/openclaw.json`：
`gateway.auth.token == 'dev-local-token'`、全树无非空 `apiKey`、`channels == {}`。

验证脚本内联在 `build-release.ps1` 的 here-string 里（`$verifySrc`），运行时写成
`%TEMP%\lxup-verify-factory-<时间戳>.py`（UTF-8 无 BOM）交给便携 python 执行，跑完自动删除。
`build-release.ps1` 会自动做这一步；想单独跑就把那段 here-string 存成 .py：

```powershell
& $PY "$env:TEMP\lxup-verify-factory-<时间戳>.py" "<zip路径>" "D:\lxup"
# 退出码 0 = 通过；非 0 = 打印失败项清单（只打印密钥所在的 JSON 路径，绝不打印密钥值）
```

> 为什么不做成 `python - <<EOF` 那样的管道内联：Windows PowerShell 5.1 管道给 native 命令的
> 字符串按 `$OutputEncoding`（默认 ASCII）编码，中文条目名（`LXUP启动器.exe`）会变成 `?`。
> 落成 UTF-8 临时文件最稳。同理 `build-release.ps1` 本体必须存成 **UTF-8 with BOM**。

扫描是**全量解压比对**（包未压缩上 GB），跑几分钟属正常。

### ③ 解压冒烟（起真实网关，验 18789 就绪）

前置：母版 `D:\lxup` 的网关**不能在跑**（端口 18789 与母版共用，会撞）；**需要联网**（见 §7）。

```powershell
$pkg = Join-Path $env:TEMP ("lxup-smoke-" + (Get-Date -Format yyyyMMdd-HHmmss))
Expand-Archive -LiteralPath "D:\lxup-release-2.4.0\LXUP-factory-v2.4.0.zip" -DestinationPath $pkg -Force

$env:OPENCLAW_STATE_DIR = "$pkg\runtime\openclaw-home"     # 关键：状态目录指向包内
$env:PATH = "$pkg\runtime\data;$pkg\runtime\python\cpython-3.11.15-windows-x86_64-none;$env:PATH"
Push-Location $pkg                                          # cwd 必须是包根
& "$pkg\runtime\data\node.exe" `
  "$pkg\runtime\openclaw\node_modules\openclaw\openclaw.mjs" `
  gateway --port 18789 --force
```

另开一个窗口确认就绪（启动器口径：最长等 120 s）：

```powershell
1..120 | ForEach-Object { if (Test-NetConnection 127.0.0.1 -Port 18789 -InformationLevel Quiet -WarningAction SilentlyContinue) { "READY"; break }; Start-Sleep 1 }
```

看到 `READY` 即冒烟通过；失败就看控制台/网关日志里是不是 `Missing config`（①漏了）或
`plugin path not found`（②漏了）或 `'npm.cmd' 不是内部或外部命令`（③漏了）。
收尾：Ctrl-C 掉网关，`Remove-Item Env:OPENCLAW_STATE_DIR`，删临时目录。

> 这一步没有自动化进 `build-release.ps1`：它会占端口、要联网、耗时数分钟，
> 且和母版进程互斥，适合发版前人工跑一次。

## 7. 已知边界

- ⚠️ **openclaw 本体必须 pin 到 stable `2026.7.1-2`**（`bootstrap-openclaw.bat` 已写死 `openclaw@2026.7.1-2`）——**绝不能用裸名 `npm install openclaw`（= 取 latest/beta）**。一旦把本体装到 beta 通道（如 `2026.7.1-beta.6`），首启迁移就会按 `@beta` 去 registry 拉 deepseek/qwen 插件，而 beta 插件已漂到要求 openclaw ≥2026.9.5、与锁定的旧本体不兼容 → 迁移失败、网关拒绝就绪。本机踩过：一次裸名 `npm install openclaw` 把 `2026.7.1-2` 刷成 `2026.7.1-beta.6`，联网首启即崩；换回 stable `2026.7.1-2` 后 stable 通道现拉的插件与 host 配套，才恢复正常。**这条是交付的硬前提。**
- **客户机首次启动需联网**：网关会自动往 `openclaw-home/npm`、`openclaw-home/projects`
  补装 4 个插件 + qwen。装完之后可以离线运行。
- **完全离线首启会卡在插件迁移**（不是崩溃，是一直卡住）。所以出厂包交付后，
  第一次开机务必联网；或在出厂前预先把 `openclaw-home/npm`、`projects` 也预置进包（当前口径不预置）。
- 出厂包不含 `hermes-home` / `codex-home`（登录态、会话、密钥都在里面），客户机首次使用各引擎时需自行登录/引导。
- 三套 LXUP 副本（`D:\lxup`、`D:\U\lxup`、USB 版）端口 5173/7889/8080/18789 完全重叠，**绝不能同时跑**。
- `runtime/python/` 下若又出现新的旧版解释器目录，记得同步加进 `EXCLUDE_DIRS`，
  否则包里会多出一份 ~200 MB 的 python。

## 8. 换机器 checklist

1. 仓库整个 clone/拷到新机器，确认 `runtime/` 在（python、node、openclaw、codex 本体都不入 git，需单独拷）。
   没有现成 `runtime/` 就在本机按 `bootstrap-openclaw.bat` / `bootstrap-hermes.bat` / `bootstrap-codex.bat` 依次引导生成；其中 **openclaw 那步会联网装引擎、并把系统 npm 自动 stage 进 `runtime/data`**（见 §2 ③），**不用手工补 npm**。
2. `runtime/version.json` 的 version 改成本次要发的号。
3. 确认 `runtime/python/cpython-3.11.*` 里有 `Scripts\pyinstaller.exe`（没有就 `pip install pyinstaller --break-system-packages`）。
4. 跑 `powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1`。
5. 按 §6 ③ 做一次解压冒烟，然后登记 sha256 发版。
